# Multimodal search using ML inference processors

This tutorial shows you how to search text and image data using the [Amazon Bedrock Titan Multimodal Embeddings model](https://docs.aws.amazon.com/bedrock/latest/userguide/titan-multiemb-models.html) (`amazon.titan-embed-image-v1`) and ML inference processors. Using the processors, you can search an index by text, by image, or by text and image together, using one search pipeline. For more information about multimodal search, see [Multimodal search]({{site.url}}{{site.baseurl}}/vector-search/ai-search/multimodal-search/).

In this tutorial, you'll use the following OpenSearch components:
- [ML inference ingest processor]({{site.url}}{{site.baseurl}}/ingest-pipelines/processors/ml-inference/)
- [ML inference search request processor]({{site.url}}{{site.baseurl}}/search-plugins/search-pipelines/ml-inference-search-request/)
- [k-NN query]({{site.url}}{{site.baseurl}}/query-dsl/specialized/k-nn/)

For a related example in Python, see the [e-commerce demo notebook](https://github.com/opensearch-project/ml-commons/blob/main/docs/tutorials/ml_inference/ecommerce_demo.ipynb), which uses ML inference processors to index product images and search them by text or image.

The steps in this tutorial use self-managed OpenSearch, with AWS access keys in the connector credentials. If using Amazon OpenSearch Service, see [Using Amazon OpenSearch Service](#using-amazon-opensearch-service).
{: .note}

Replace the placeholders beginning with the prefix `your_` with your own values.
{: .note}

## Step 1: Create an embedding model

Follow these steps to create and test the embedding model.

### Step 1.1: Create a connector

To create a connector for the model, send the following request. Because you'll use ML inference processors in this tutorial, you don't need to specify a pre- or post-processing function in the connector:

```json
POST /_plugins/_ml/connectors/_create
{
  "name": "Amazon Bedrock connector: Titan Multimodal Embeddings",
  "description": "The connector to the Amazon Bedrock Titan Multimodal Embeddings model",
  "version": 1,
  "protocol": "aws_sigv4",
  "credential": {
    "access_key": "your_aws_access_key",
    "secret_key": "your_aws_secret_key",
    "session_token": "your_aws_session_token"
  },
  "parameters": {
    "region": "your_aws_region",
    "service_name": "bedrock",
    "model": "amazon.titan-embed-image-v1"
  },
  "actions": [
    {
      "action_type": "predict",
      "method": "POST",
      "headers": {
        "content-type": "application/json"
      },
      "url": "https://bedrock-runtime.${parameters.region}.amazonaws.com/model/${parameters.model}/invoke",
      "request_body": "{\"inputText\": \"${parameters.inputText:-null}\", \"inputImage\": \"${parameters.inputImage:-null}\"}"
    }
  ]
}
```
{% include copy-curl.html %}

The model accepts text in the `inputText` parameter and a Base64-encoded image in the `inputImage` parameter. The `:-null` suffix sets a parameter to `null` when the request doesn't provide it, so you can send text, an image, or both.

The response contains a connector ID:

```json
{
  "connector_id": "P8c_JZUB7judm8f4591w"
}
```

Note the connector ID; you'll use it in the next step.

### Step 1.2: Register and deploy the model

To register and deploy the model, send the following request:

```json
POST /_plugins/_ml/models/_register?deploy=true
{
  "name": "Amazon Bedrock Titan Multimodal Embeddings",
  "function_name": "remote",
  "description": "Multimodal embedding model",
  "connector_id": "P8c_JZUB7judm8f4591w"
}
```
{% include copy-curl.html %}

The response contains the model ID:

```json
{
  "task_id": "nMdJJZUB7judm8f4HN29",
  "status": "CREATED",
  "model_id": "ncdJJZUB7judm8f4HN3P"
}
```

Note the model ID; you'll use it in the following steps.

### Step 1.3: Test the model

To test the model, send the following request. To generate an embedding for an image, provide a Base64-encoded image in the `inputImage` parameter. If you provide both `inputText` and `inputImage`, the model generates one embedding that represents both inputs:

```json
POST /_plugins/_ml/models/ncdJJZUB7judm8f4HN3P/_predict
{
  "parameters": {
    "inputText": "Say this is a test"
  }
}
```
{% include copy-curl.html %}

Because the connector has no post-processing function, the response contains the model output in the `dataAsMap` object. The `embedding` field contains the embedding generated by the model:

```json
{
  "inference_results": [
    {
      "output": [
        {
          "name": "response",
          "dataAsMap": {
            "embedding": [
              0.022338867,
              ...
            ],
            "inputTextTokenCount": 7,
            "message": null,
            "successCount": null,
            "failureCount": null,
            "results": null
          }
        }
      ],
      "status_code": 200
    }
  ]
}
```

## Step 2: Create an ingest pipeline

Create an ingest pipeline containing an ML inference processor. The processor's `input_map` passes the document's `name` field to the model's `inputText` parameter and the `image` field to the `inputImage` parameter. The `output_map` stores the `embedding` field from the model output in a new document field named `multimodal_embedding`:

```json
PUT /_ingest/pipeline/ml_inference_pipeline_multimodal
{
  "description": "Generate multimodal embeddings for ingested documents",
  "processors": [
    {
      "ml_inference": {
        "tag": "ml_inference",
        "model_id": "ncdJJZUB7judm8f4HN3P",
        "input_map": [
          {
            "inputText": "name",
            "inputImage": "image"
          }
        ],
        "output_map": [
          {
            "multimodal_embedding": "embedding"
          }
        ],
        "ignore_missing": true,
        "ignore_failure": true
      }
    }
  ]
}
```
{% include copy-curl.html %}

Both input fields are in one `input_map` object, so the processor invokes the model once per document. Because `ignore_missing` is `true`, a document that contains only one of the two fields is still sent to the model, and a document that contains neither is indexed without an embedding.

## Step 3: Create an index and ingest data

To create a vector index that uses the ingest pipeline by default, send the following request. The dimension of the `multimodal_embedding` field matches the model's default embedding length of 1,024:

```json
PUT /my-multimodal-index
{
  "settings": {
    "index.knn": true,
    "default_pipeline": "ml_inference_pipeline_multimodal"
  },
  "mappings": {
    "properties": {
      "multimodal_embedding": {
        "type": "knn_vector",
        "dimension": 1024
      }
    }
  }
}
```
{% include copy-curl.html %}

Ingest three documents into the index. The first document contains only text, the second contains text and a Base64-encoded image, and the third contains neither a `name` nor an `image` field. In the following request, the Base64 string is truncated; replace it with a full Base64-encoded image:

```json
POST _bulk
{ "index": { "_index": "my-multimodal-index", "_id": "1" } }
{ "name": "Central Park", "category": "Park" }
{ "index": { "_index": "my-multimodal-index", "_id": "2" } }
{ "name": "Times Square", "category": "Square", "image": "iVBORw0KGgoAAAANSUhEUgAAAFcAAAAdCAYAAADfC/BmAAAAAXNSR0IArs4c6QAAAGJlWElmTU0AKgAAAA..." }
{ "index": { "_index": "my-multimodal-index", "_id": "3" } }
{ "category": "Bridge" }
```
{% include copy-curl.html %}

To verify that the pipeline generated an embedding from the text and image, retrieve the second document:

```json
GET /my-multimodal-index/_doc/2
```
{% include copy-curl.html %}

The document contains the generated `multimodal_embedding` field:

```json
{
  "_index": "my-multimodal-index",
  "_id": "2",
  "_version": 1,
  "_seq_no": 1,
  "_primary_term": 1,
  "found": true,
  "_source": {
    "multimodal_embedding": [
      0.026977539,
      ...
    ],
    "image": "iVBORw0KGgoAAAANSUhEUgAAAFcAAAAdCAYAAADfC/BmAAAAAXNSR0IArs4c6QAAAGJlWElmTU0AKgAAAA...",
    "name": "Times Square",
    "category": "Square"
  }
}
```

The first document contains an embedding generated from the `name` field only. The third document is indexed without a `multimodal_embedding` field because it contains no fields in the `input_map`.

## Step 4: Create a search pipeline

Create a search pipeline containing an ML inference search request processor. The processor rewrites the search request into a `knn` query that uses the embedding generated from the query text, the query image, or both:

```json
PUT /_search/pipeline/multimodal_semantic_search_pipeline
{
  "request_processors": [
    {
      "ml_inference": {
        "tag": "ml_inference",
        "description": "Generates an embedding from the query text or image and runs a k-NN query",
        "model_id": "ncdJJZUB7judm8f4HN3P",
        "query_template": "{\"query\": {\"knn\": {\"multimodal_embedding\": {\"vector\": ${multimodal_embedding}, \"k\": 3}}}}",
        "optional_input_map": [
          {
            "inputText": "ext.ml_inference.text",
            "inputImage": "ext.ml_inference.image"
          }
        ],
        "output_map": [
          {
            "multimodal_embedding": "embedding"
          }
        ],
        "model_config": {},
        "ignore_missing": false,
        "ignore_failure": false
      }
    }
  ]
}
```
{% include copy-curl.html %}

The processor contains the following settings:

- The `optional_input_map` maps the `ext.ml_inference.text` and `ext.ml_inference.image` fields in the search request to the model's `inputText` and `inputImage` parameters. The processor passes only the fields that are present in the request to the model, so a search request can contain text, an image, or both. A search request must contain at least one of the fields: if it contains neither, the processor sends the model a request without input, and the model returns an error. If you use `input_map`, both fields must be present in every search request.
- The `output_map` stores the `embedding` field from the model output in the `multimodal_embedding` variable.
- The `query_template` defines the query that replaces the original query in the search request. The template inserts the `multimodal_embedding` variable as the query vector.

## Step 5: Search the index

When you search using the pipeline, the processor replaces the query in the request with the `knn` query from the `query_template`. The following examples send a `match_all` query, which the processor replaces.

### Search by text

To search the index by text, provide the query text in the `ext.ml_inference.text` field:

```json
GET /my-multimodal-index/_search?search_pipeline=multimodal_semantic_search_pipeline
{
  "query": {
    "match_all": {}
  },
  "ext": {
    "ml_inference": {
      "text": "place where recreational activities are done, picnics happen there"
    }
  }
}
```
{% include copy-curl.html %}

The response contains the two documents that have embeddings. The `Central Park` document is the closest match:

```json

      "value": 2,

    },
    "max_score": 0.5640698,

      {

        "_id": "1",

        "_source": {
          "multimodal_embedding": [
            0.01171875,
            ...
```

To view the query that the processor generated, add the `verbose_pipeline=true` query parameter to the search request:

```json
GET /my-multimodal-index/_search?search_pipeline=multimodal_semantic_search_pipeline&verbose_pipeline=true
```


## Using Amazon OpenSearch Service

In Amazon OpenSearch Service, the connector uses an AWS Identity and Access Management (IAM) role to invoke the model. Steps 2--5 of this tutorial are the same. To create the connector, follow Steps 1--3 of [Semantic search using Amazon Bedrock Titan]({{site.url}}{{site.baseurl}}/tutorials/vector-search/semantic-search/semantic-search-bedrock-titan/), making the following changes:

- In the permissions of the role that invokes the model, set the resource to `arn:aws:bedrock:*::foundation-model/amazon.titan-embed-image-v1`.
- In the Python code that creates the connector, use the following connector payload, which replaces the access keys with the IAM role ARN:

```python
payload = {
  "name": "Amazon Bedrock connector: Titan Multimodal Embeddings",
  "description": "The connector to the Amazon Bedrock Titan Multimodal Embeddings model",
  "version": 1,
  "protocol": "aws_sigv4",
  "credential": {
    "roleArn": "your_iam_role_arn_created_in_step1"
  },
  "parameters": {
    "region": "your_aws_region",
    "service_name": "bedrock",
    "model": "amazon.titan-embed-image-v1"
  },
  "actions": [
    {
      "action_type": "predict",
      "method": "POST",
      "headers": {
        "content-type": "application/json"
      },
      "url": "https://bedrock-runtime.${parameters.region}.amazonaws.com/model/${parameters.model}/invoke",
      "request_body": "{\"inputText\": \"${parameters.inputText:-null}\", \"inputImage\": \"${parameters.inputImage:-null}\"}"
    }
  ]
}
```
{% include copy.html %}

Then register and deploy the model as described in [Step 1.2](#step-12-register-and-deploy-the-model).
