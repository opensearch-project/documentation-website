# RAG chatbot

One of the known limitations of large language models (LLMs) is that their knowledge base only contains information from the period of time during which they were trained. LLMs have no knowledge of recent events or of your internal data. You can augment the LLM knowledge base by using retrieval-augmented generation (RAG).

This tutorial shows you how to build your own chatbot using [agents and tools]({{site.url}}{{site.baseurl}}/ml-commons-plugin/agents-tools/index/) and RAG. RAG supplements the LLM knowledge base with information contained in OpenSearch indexes.

Replace the placeholders beginning with the prefix `your_` with your own values.
{: .note}

## Prerequisite

Meet the prerequisite and follow Step 1 of the [RAG with a conversational flow agent tutorial]({{site.url}}{{site.baseurl}}/ml-commons-plugin/tutorials/rag-conversational-agent/) to set up the `test_population_data` knowledge base index, which contains US city population data.

Note the embedding model ID; you'll use it in the following steps.

## Step 3: Create an agent

For this tutorial, you will create an agent of the `conversational` type. 

Both the `conversational_flow` and `conversational` agents support conversation history.

The `conversational_flow` and `conversational` agents differ in the following ways:

- A `conversational_flow` agent runs tools sequentially, in a predefined order.
- A `conversational` agent dynamically chooses which tool to run next.

In this tutorial, the agent includes two tools: One provides recent population data, and the other contains tech news.

The agent has the following parameters:

- `"max_iteration": 5`: The agent runs the LLM a maximum of five times.
- `"response_filter": "$"`: Passes the full model response to the agent so that the agent can read the tool calls in it. This setting overrides the connector's `response_filter`.
- `"prompt": "${parameters.question}"`: Sends the user question to the LLM as the user message.
- `"_llm_interface": "bedrock/converse/claude"` (in the agent `parameters`): Uses the tool calling (function calling) interface of the Amazon Bedrock Converse API for Claude models.
- `"doc_size": 3` (in `population_data_knowledge_base`): Specifies to return the top three documents.

Create an agent with the preceding specifications:

```json
POST _plugins/_ml/agents/_register
{
  "name": "Chat Agent with RAG",
  "type": "conversational",
  "description": "this is a test agent",
  "llm": {
    "model_id": "your_llm_model_id",
    "parameters": {
      "max_iteration": 5,
      "response_filter": "$",
      "prompt": "${parameters.question}"
    }
  },
  "memory": {
    "type": "conversation_index"
  },
  "parameters": {
    "_llm_interface": "bedrock/converse/claude"
  },
  "tools": [
    {
      "type": "VectorDBTool",
      "name": "population_data_knowledge_base",
      "description": "This tool provides population data of US cities.",
      "parameters": {
        "input": "${parameters.question}",
        "index": "test_population_data",
        "source_field": [
          "population_description"
        ],
        "model_id": "your_text_embedding_model_id",
        "embedding_field": "population_description_embedding",
        "doc_size": 3
      }
    },
    {
      "type": "VectorDBTool",
      "name": "tech_news_knowledge_base",
      "description": "This tool provides recent tech news.",
      "parameters": {
        "input": "${parameters.question}",
        "index": "test_tech_news",
        "source_field": [
          "passage"
        ],
        "model_id": "your_text_embedding_model_id",
        "embedding_field": "passage_embedding",
        "doc_size": 2
      }
    }
  ],
  "app_type": "chat_with_rag"
}
```

## Using the Search Index tool with a neural query

You can also build the agent in this tutorial using the [Search Index tool]({{site.url}}{{site.baseurl}}/ml-commons-plugin/agents-tools/tools/search-index-tool/) in place of the [VectorDB tool]({{site.url}}{{site.baseurl}}/ml-commons-plugin/agents-tools/tools/vector-db-tool/). Each `SearchIndexTool` contains a complete search request with an embedded `neural` query. The agent uses function calling: the LLM chooses a tool and provides the question to search for, and the tool runs the `neural` query using that question.

This section uses the `test_population_data` and `test_tech_news` indexes and the text embedding model from the preceding steps.

### Step 1: Prepare an LLM for function calling

Function calling requires a connector that returns the full Amazon Bedrock Converse API response, so that the agent can read the tool calls the model makes. For this reason, the following connector does not specify a `response_filter`. It also passes a system prompt to the model.

Create a connector for the Claude model:

```json
POST /_plugins/_ml/connectors/_create
{
  "name": "Amazon Bedrock Claude Sonnet 4.6 connector",
  "description": "Connector to Amazon Bedrock Converse API for the Claude model",
  "version": 1,
  "protocol": "aws_sigv4",
  "parameters": {
    "region": "us-east-1",
    "service_name": "bedrock",
    "model": "us.anthropic.claude-sonnet-4-6"
  },
  "credential": {
    "access_key": "your_aws_access_key",
    "secret_key": "your_aws_secret_key",
    "session_token": "your_aws_session_token"
  },
  "actions": [
    {
      "action_type": "predict",
      "method": "POST",
      "url": "https://bedrock-runtime.${parameters.region}.amazonaws.com/model/${parameters.model}/converse",
      "headers": {
        "content-type": "application/json"
      },
      "request_body": "{ \"system\": [{\"text\": \"${parameters.system_prompt}\"}], \"messages\": [${parameters._chat_history:-}{\"role\":\"user\",\"content\":[{\"text\":\"${parameters.prompt}\"}]}${parameters._interactions:-}]${parameters.tool_configs:-} }"
```

```json
  ]
}
```

### Step 2: Register the agent

Register a `conversational` agent containing two `SearchIndexTool` tools, one for each knowledge base index. The agent and its tools are configured as follows:

- `parameters._llm_interface`: Set to `bedrock/converse/claude` so that the agent sends tool definitions to the model and parses tool calls from the Converse API response.
- `llm.parameters.system_prompt`: Instructs the LLM to retrieve information for each topic in a question.
- `llm.parameters.prompt`: Sends the user question to the LLM.
- `tools.parameters.input`: Builds the tool input from the tool's `index` and `query` parameters.
- `tools.parameters.query`: A search request containing a `neural` query. The `query_text` is `${parameters.question}`, which the agent fills with the question the LLM provides when it calls the tool. The `neural` query uses the text embedding model to convert the question into a vector. The `size` field limits the results to the top two documents, and `_source` returns only the text field.
- `tools.attributes.input_schema`: A [JSON schema](https://json-schema.org/) that defines the tool input the LLM must provide. In this example, the LLM provides a `question` string.
- `tools.attributes.strict`: Whether function calling must strictly follow the input schema. This example sets it to `false`.

For more information about these fields, see [Register Agent API]({{site.url}}{{site.baseurl}}/ml-commons-plugin/api/agent-apis/register-agent/).

To register the agent, send the following request:

```json
POST /_plugins/_ml/agents/_register
{
  "name": "RAG agent with Search Index tools",
  "type": "conversational",
  "description": "An agent that answers questions using population data and tech news",
  "app_type": "rag",
  "llm": {
    "model_id": "your_function_calling_model_id",
    "parameters": {
      "max_iteration": 10,
      "system_prompt": "You are a helpful assistant. Use the available tools to retrieve the information needed to answer the question. If a question covers several topics, retrieve information for each topic and then answer all parts of the question.",
      "prompt": "${parameters.question}"
    }
  },
  "memory": {
```

#### Retrieve message traces

The agent stores each step it performs as a trace of the message. To retrieve the traces, provide the `parent_interaction_id` from the response as the message ID in a [Get Message Traces API]({{site.url}}{{site.baseurl}}/ml-commons-plugin/api/memory-apis/get-message-traces/) request:

```json
GET /_plugins/_ml/memory/message/srx5hZkBc62yu84LcN1v/traces
```
{% include copy-curl.html %}

The response contains a `traces` array, which lists the steps in the order in which the agent performed them. For steps in which the agent calls the LLM, the `origin` field is `LLM`. For tool calls, the `origin` field contains the tool name, the `input` field contains the tool input that the LLM provided, and the `response` field contains the tool output.
